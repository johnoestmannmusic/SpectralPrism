## Project: SpectralPrism

**Project Title:** SpectralPrism — Spectral Freeze Instrument Plugin
**Project Description:** A Rust nih-plug/egui VST3/CLAP instrument that freezes a spectral snapshot of a loaded sample at a chosen "Freeze Point" and loops it indefinitely as a sustained pad/drone, shaped by Formant Shift, Stereo Width, Loop Length, and a full ADSR/velocity/pitch-bend/pan voice architecture.
**Implementation Repository:** this repository (`crates/prism_dsp`, `crates/prism_plugin`, `crates/prism_cli`, `xtask`).
**Board Last Updated:** 2026-09-11 13:14 by Claude Sonnet 5

### Ideas

#### SP-IDEA-001 — FM fusion mode ("waveforms act as operators")

- **Card Title:** FM fusion mode
- **Description:** A 10th Spectral Fusion algorithm where Sample A's and Sample B's frozen spectra modulate each other continuously (FM synthesis-style, "operators") rather than combining once. Architecturally bigger than every other Fusion mode shipped in SP-PLAN-001: those are all one-shot combines (either two `FrozenSpectrum`s combined once before resynthesis, or two fully-resynthesized audio buffers combined once after). FM instead needs one signal to continuously modulate the other's instantaneous phase/frequency *during* the per-hop resynthesis loop (`prism_dsp::resynth::FreezeResynth::next_frame`), which means changing the resynthesis engine itself (e.g. a second phase accumulator feeding into the first's phase advance every hop), not adding a sibling combine function next to `prism_dsp::fusion`'s existing ones. Deserves its own dedicated design pass rather than being bolted on.

#### SP-PLAN-005 — Init preset unloads samples for a true "back to default"

- **Card Title:** Init preset unloads samples
- **Description:** The user's own hand-made factory-style "Init" preset (`~/.config/SpectralPrism/presets/Init.spjson`, `sample_path`/`sample_path_b` both already `null`) was expected to act as a true "back to default," but `apply_preset` had always treated a `null` sample path as "leave whatever's currently loaded untouched" (the right default for an ordinary preset that just doesn't reference a sample, e.g. "load only the ADSR settings") - so loading Init over an already-loaded sample left that sample playing. Added a new `Preset` field, `unload_samples: bool` (`#[serde(default)]`, never set by the ordinary Save flow), which `apply_preset` checks first: when true, it unloads Sample A and Sample B entirely (clears `source`/`source_b` to empty, clears both `sample_path` params, clears both `loaded_filename`s, and re-renders) instead of its normal leave-alone behavior. Hardcoded `"unload_samples": true` directly into the user's existing `Init.spjson` file (at their request - "feel free to hardcode this preset in") rather than building an auto-detection mechanism keyed on the preset's name.

#### SP-PLAN-003 — Tune (per-sample retune, pre-Freeze/pre-Fusion)

- **Card Title:** Tune
- **Description:** A new "Tune" control for both Sample A and Sample B, letting each be retuned by a numerical value in semitones (decimal values supported, for microtonal tuning) so two differently-pitched samples can be lined up to the same tone before they're frozen or fused. Applies to the *input* sample, before `analyze_freeze_point` runs - distinct from Formant Shift, which reshapes the already-frozen spectrum's envelope after the fact. Implemented as a vari-speed resample (`prism_dsp::resample::apply_tune`): reuses the existing `resample_linear` whole-buffer resampler, lying about the source rate by the semitone ratio (`formant::semitones_to_ratio`) to compress/expand the buffer, which shifts pitch when the result is later played back at the unchanged nominal rate - no new resampling algorithm needed. While implementing this the user also asked to remove the Audition Fusion mode, since Mix already covers its use case (Mix at 100% is exactly "B alone") - see the note on SP-PLAN-001.
